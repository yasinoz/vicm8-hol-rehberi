## Bölüm A — Kavramlar

### vCenter yönetimi: roller ve izinler
vCenter'da "kim neyi yapabilir" **izin (permission)** modeliyle belirlenir:
- **Rol (Role):** yetki kümesi (ör. "Administrator", "Read-only", ya da özel).
- **İzin = Kullanıcı/Grup + Rol + Nesne.** Bir izni envanterdeki bir nesneye
  (vCenter, Datacenter, Cluster, VM…) uygularsın; alt nesnelere **miras** kalır.
> Mantık CUCM'deki değil ama IT'deki klasik "en az yetki" ilkesidir: stajyere
> "Read-only", operatöre dar bir özel rol.

### Sanal ağlar — iki anahtar türü
VM'ler fiziksel ağa **sanal anahtar** üzerinden çıkar:

| Tür | Kapsam | Ne zaman |
|---|---|---|
| **vSphere Standard Switch (vSS)** | **Tek host**'a özel | Küçük ortam; her host'ta ayrı ayrı yapılandırılır |
| **vSphere Distributed Switch (vDS)** | **Küme geneli** (vCenter yönetir) | Birçok host; tutarlı, merkezi ağ politikası |

- **Port Group:** Anahtar üzerinde, aynı ağ politikasını (VLAN, güvenlik,
  teaming) paylaşan VM'lerin bağlandığı "kapı grubu".
- **VMkernel port:** Host'un kendi servisleri için (yönetim, vMotion, vSAN,
  depolama trafiği).

> **8 ↔ 9.1 farkı:** vDS sürümü yenidir; kavram (vSS tek host / vDS küme
> geneli, port group, VMkernel) **aynıdır**.

### Depolama — datastore türleri
VM dosyaları bir **datastore**'da durur:

| Tür | Nedir |
|---|---|
| **VMFS** | ESXi'nin blok depolama (FC/iSCSI/yerel disk) dosya sistemi |
| **NFS** | Ağ dosya paylaşımı üzerinden datastore |
| **vSAN** | Host'ların yerel disklerini birleştirip **yazılım tanımlı** paylaşımlı depolama kuran teknoloji |

**vSAN mantığı:** Ayrı bir depolama cihazı almak yerine, küme içindeki
host'ların diskleri havuzlanır; **Storage Policy (SPBM)** ile her VM'e "kaç
kopya, ne performans" kuralını sen verirsin.

## Bölüm C — Eğitmen lab demosu (tam adımlar)

### C.1 — Standard Switch (vSS) + Port Group
1. Host → **Configure** → **Networking** → **Virtual switches** → **Add
   Networking**.
2. **Connection type** seç:
   - **Virtual Machine Port Group for a Standard Switch** (VM ağı için), ya da
   - **VMkernel Network Adapter** (host servisleri: yönetim / vMotion / vSAN).
3. **New standard switch** (ya da mevcut) → bir **uplink** (boş fiziksel NIC)
   ata → **Next**.
4. **Network label** (port group adı, ör. `PG-VLAN10`) + **VLAN ID** → **Next**
   → **Finish**.
5. **VMkernel örneği (vMotion):** yukarıda VMkernel seç → **vMotion** servisini
   işaretle → statik IP ver → **Finish**.

### C.2 — VM'i port group'a bağlama
1. VM → **Edit Settings** → **Network adapter 1** → açılır listeden
   oluşturduğun **port group**'u seç → **OK**.
2. VM içinden ağ/ping ile doğrula.

### C.3 — Distributed Switch (vDS)
1. Üstten **Networking** görünümü → **Datacenter** sağ tık → **Distributed
   Switch** → **New Distributed Switch** → ad + sürüm + **uplink sayısı** →
   **Finish**.
2. vDS sağ tık → **Add and Manage Hosts** → **Add hosts** → host(lar)ı seç →
   fiziksel NIC'leri **uplink**'lere ata → (gerekirse) VMkernel'leri taşı →
   **Finish**.
3. vDS sağ tık → **Distributed Port Group** → **New Distributed Port Group** →
   ad + **VLAN** → **Finish**.
4. VM'leri vDS port group'a taşı (VM **Edit Settings** ya da vDS → **Migrate VM
   to Another Network**).

### C.4 — iSCSI datastore (VMFS)
1. Host → **Configure** → **Storage Adapters** → **Add Software Adapter** →
   **Add software iSCSI adapter**.
2. iSCSI adaptörü → **Dynamic Discovery** → **Add** → hedef **IP:3260** → **OK**
   → **Rescan Storage**.
3. Host → **Configure** → **Datastores** (ya da **Storage** → **New Datastore**)
   → **VMFS** → keşfedilen LUN'u seç → ad + VMFS sürümü → **Finish**.

### C.5 — NFS datastore
1. **Storage** → **New Datastore** → **NFS** → sürüm (**NFS 3** veya **4.1**).
2. **NFS Server** adresi + **Folder** (export path, ör. `/mnt/vol1`) + datastore
   adı → erişecek host(lar)ı seç → **Finish**.
3. Yeni datastore tüm host'larda görünür. Bir VM'i **Migrate → Change storage
   only** ile bu datastore'a taşıyarak test et.
