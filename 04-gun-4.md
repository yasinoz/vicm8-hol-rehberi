## Bölüm A — Kavramlar

### Kaynak kontrolleri — üç ayar
Bir VM (ya da resource pool) CPU/RAM için üç şeyle ayarlanır:

| Ayar | Anlamı | Ne zaman devreye girer |
|---|---|---|
| **Reservation** | **Garanti** edilen minimum (MHz / MB) | Her zaman ayrılır |
| **Limit** | **Tavan** — bundan fazlasını alamaz | Üst sınır gerekiyorsa |
| **Shares** | **Çekişme anında** göreli öncelik (Low/Normal/High ya da sayı) | Kaynak **yetmediğinde** |

> **Anahtar:** Shares yalnızca **kaynak kıtlığında** önemlidir — bolken herkes
> istediğini alır. Reservation "garanti", Limit "tavan", Shares "kavgada pay".

### Resource Pool (kaynak havuzu)
Bir cluster'ın CPU/RAM'ini **mantıksal gruplara** böler (ör. "Üretim" havuzu
yüksek öncelik, "Test" havuzu düşük). Havuza shares/limit/reservation verirsin;
içindeki VM'ler bu havuzun payını paylaşır.

### İzleme: grafikler + alarmlar
- **Performance Charts:** vSphere Client'te host/VM için CPU, bellek, disk, ağ
  grafikleri (gerçek zamanlı ve geçmiş).
- **Alarms (uyarılar):** Bir eşik aşılınca (ör. CPU %90) tetiklenen uyarı/eylem.
- **esxtop:** ESXi kabuğunda (SSH) **canlı, satır satır** performans aracı —
  CPU (%RDY, %USED), bellek, disk gecikmesi. Derin analizde başvurulur.

> **%RDY (CPU Ready):** VM'in çalışmak için CPU beklediği süre. Yüksekse
> → aşırı yoğunluk/overcommit. İzlemede altın metriklerden.

## Bölüm C — Eğitmen lab demosu (tam adımlar)

### C.1 — Reservation / Limit / Shares
1. VM → **Edit Settings** → **CPU**'yu genişlet → **Reservation** (MHz),
   **Limit** (MHz), **Shares** (Low/Normal/High/Custom). Aynısını **Memory**
   için yap → **OK**.
2. **Çekişmeyi göster:** bir host'ta kaynağı doldur (CPU yükü üreten araç); iki
   VM'den birine **High**, öbürüne **Low** shares ver → yük altında High olanın
   daha çok CPU aldığını **Performance** grafiğinde göster.

### C.2 — Resource pool
1. Cluster sağ tık → **New Resource Pool** → ad `RP-Uretim` → CPU/Memory
   **Shares = High**, istenirse Reservation/Limit → **OK**. İkinci havuz:
   `RP-Test`, **Shares = Low**.
2. VM'leri **sürükle-bırak** ile havuzlara taşı.
3. Havuz → **Monitor** → **Resource Allocation** ile payları göster.

### C.3 — Alarm tanımı
1. Bir nesne (vCenter/cluster/host/VM) → **Configure** → **Alarm Definitions**
   → **Add**.
2. **Ad** + **Target type** (ör. Virtual Machine) → **Next**.
3. **Trigger:** ör. *VM CPU Usage > 90% for 5 min* → **Severity** (Warning/
   Critical).
4. **(Opsiyonel) Action:** e-posta / SNMP / komut → **Create**.
5. **Tetikle:** VM'de CPU yükselt → alarmın **kırmızı** olduğunu **Triggered
   Alarms**'ta göster → **Acknowledge / Reset**.

### C.4 — Performance charts
1. Host/VM → **Monitor** → **Performance** → **Advanced**.
2. **Chart Options** ile metrik seç: CPU **Ready** ve **Usage**, Memory, Disk
   **latency**, Network.
3. Zaman aralığını (**Real-time** / 1 gün) değiştir, grafikleri yorumla.

### C.5 — esxtop (canlı analiz)
1. Host → **Configure** → **Services** → **SSH** → **Start** (SSH'ı aç).
2. **PuTTY** ile host'a bağlan (root).
3. `esxtop` yaz → CPU ekranı gelir. Ekranlar arası geç: **`c`** CPU, **`m`**
   bellek, **`d`** disk, **`n`** ağ.
4. **%RDY** (CPU Ready) yüksek VM var mı bak (yüksek = overcommit/sıkışma).
   **`q`** ile çık.

## Sık sorunlar
| Belirti | Çözüm |
|---|---|
| esxtop bağlanmıyor | Host SSH açık mı; PuTTY'de doğru IP/kullanıcı; lab rehberindeki kimlik |
| %RDY/%USED ne demek | %RDY = CPU bekleme (yüksek=kötü), %USED = kullanılan CPU |
| Grafikte veri yok | Zaman aralığını (Real-time) seç; birkaç dk veri birikmeli |
| Shares etkisiz | Kaynak boşsa shares görünmez; etkisi **çekişmede** ortaya çıkar |
